1. Explain the login page.
Show the two roles, user ID field and show/hide password control.
Say: “The server verifies the ID, password and selected role. Interviewees cannot create slots or submit interviewer feedback.”

2. Create availability as interviewer CC2001.
Open Manage slots. Choose a future date, Software Engineering, 30 minutes, 3 slots and a 15-minute break. Read the preview and publish.
Say: “This creates three separate one-to-one interviews, not a group class. Each has one available place.”
Show the published times. Try the same start time again to show overlap rejection: no partial batch is saved.

3. Book as interviewee CC1001.
Sign out, switch roles and sign in. Open Find interviews, select Software Engineering and locate the slots you just created with Nisha.
Book one and add a goal, such as “Explain my final-year project clearly.” Open My sessions.
Say: “The server checks availability and also prevents me from booking overlapping interviews, even with different interviewers.”

4. Demonstrate cancellation.
Click Cancel interview, read the confirmation, and choose Yes, cancel interview. Open Cancelled to show the record.
Return to Find interviews and book the reopened slot.
Say: “Cancelling a booking preserves its history and makes the slot available again.”
Optional interviewer example: an interviewer can cancel one of their published slots. If it has a scheduled booking, that booking is cancelled too and the slot is removed from available choices.

5. Complete and evaluate as CC2001.
Open My sessions and choose Interview prep for the newly booked session. Show suggested questions and save a short private note.
Say: “The actual interview takes place in person or on a separately arranged call. For this demonstration, I will simulate completing it.”
Click Complete, open Completed, and click Give feedback. Enter scores and specific written feedback.
Example strength: “Explained the requirements and application workflow clearly.”
Example improvement: “Explain one validation rule with a concrete input example.”

6. Show the result as CC1001.
Open My progress and show the scores and saved advice. Refresh once to demonstrate that feedback persists.
Say: “The scores summarize peer feedback. Interviewer preparation notes are private and are not returned to the interviewee.”

SHORT VIVA ANSWERS

What is the architecture?
The browser sends HTTP requests to a Node.js server. The server validates requests, checks the user's session and role, and saves structured data in a local JSON file.

Why is this end to end?
A real action in the interface changes server data. The other role can then see the resulting booking or feedback. It is more than a collection of static screens.

How are passwords protected?
Passwords are stored as salted scrypt hashes. The browser receives a session cookie after a successful login. Server endpoints enforce permissions.

How do you prevent conflicting slots?
I compare the start and end time of each proposed slot with existing active slots. If any slot conflicts, the entire proposed batch is rejected. Bookings also check whether the interviewee already has a scheduled interview during that interval.

Why JSON instead of a database?
It keeps an individual local demonstration easy to run. The current application uses one server process. A production version should use a relational database with transactions and uniqueness constraints.

What are the limitations?
Prepared accounts, local storage, sessions that end when the server restarts, and no integrated video or email notifications. Completion is an interviewer action, so it can be demonstrated without waiting for a scheduled time. This is a coursework prototype rather than a production deployment.
